# 12: Apple Books 與 Kobo 實機驗證

**What to build:** 這是手動驗證票，需要真人和實體裝置，不寫成自動測試。用 `epubgen` 產生兩本書，分別在 Apple Books 和 Kobo 上開啟，確認同一個檔案在兩邊都能以固定版面正常閱讀：

## 驗證步驟

### 準備

```bash
.venv/bin/python scripts/make_device_test_books.py
```

腳本會在專案的 `device-test/books/`（已被 `.gitignore` 排除）產生 9 本測試書，每本各有兩個檔案：`<名稱>.epub` 與內容完全相同、只有副檔名不同的 `<名稱>.fxl.kepub.epub`。每一頁都畫有大大的頁碼（P1、P2…）、章節標籤與四個角落記號（TL、TR、BL、BR），所以翻頁方向、左右頁配對與目錄跳轉一眼就能看出對不對。9 本書都已用 EPUBCheck 5.4.0 驗證過，零錯誤零警告，所以不合法的 EPUB 結構不是變因。

| 書 | 用來驗證什麼 |
|----|-------------|
| A-rtl-chapters | RTL 預設、章節目錄（第 1 話、第 2 話、第 10 話，自然排序）、第 2 話第 2 頁是 WebP 來源（轉 JPEG）、根目錄封面圖不在目錄 |
| B-ltr-plain | LTR（`--direction ltr`）、沒有章節的目錄 |
| C-rtl-spread | RTL 雙頁（`--spread`） |
| D-ltr-spread | LTR 雙頁（`--spread --direction ltr`） |
| E-gif-cover | 第一張圖是 GIF，書櫃封面縮圖 |
| F-keep-webp | `--keep-webp`，WebP 是否顯示 |
| G-big-pages | 6 頁，每頁 3000x4500（約 13.5M 像素），翻頁速度 |
| H-big-pages-resized | 和 G 同一批圖，`--max-size 1950`，與 G 比較翻頁速度 |
| I-external-cover | 封面是資料夾外的圖（畫面上寫 EXTERNAL COVER），書櫃縮圖 |

### 一、Apple Books（iPhone、iPad、Mac 各至少試一台）

1. 把 `.epub`（不要用 `.fxl.kepub.epub`）傳到裝置：Mac 直接拖進 Books app；iPhone、iPad 用 AirDrop 或「檔案」app 選擇以 Books 開啟。
2. 書櫃：確認每本書的封面縮圖、書名（書名就是檔名，例如 `A-rtl-chapters`）。E 的縮圖應該是 GIF COVER 頁，I 的縮圖應該是 EXTERNAL COVER。
3. **A**：開啟後確認是固定版面（圖片沒有被重排、切割、拉伸）。往**右**翻到下一頁（RTL），P1→P2→P3 依序出現。打開目錄，確認有「第 1 話、第 2 話、第 10 話」三項且順序正確，點選後分別跳到 P2、P6、P9。確認 WebP 來源那頁（第 2 話第 2 頁，P7）正常顯示。
4. **B**：往**左**翻到下一頁（LTR）。目錄只有一項（書名），點選能跳到第一頁，不會出錯。
5. **C、D**：先直放，確認每頁單獨顯示；再橫放，確認封面（P1）單獨一頁，之後兩頁並排。
   - C（RTL）預期：P2 在右、P3 在左，接著 P4 右、P5 左…
   - D（LTR）預期：P2 在左、P3 在右，接著 P4 左、P5 右…
   - 記錄封面是置中、靠右、靠左，還是和 P2 擠在同一跨頁。
6. **G、H**：記錄翻頁是否明顯延遲，兩本的差別。
7. 記錄裝置型號與系統版本。

### 二、Kobo（eInk，至少一台）

側載方式：用 USB 線把閱讀器接上電腦，把檔案複製到閱讀器的根目錄，退出裝置後等它匯入。每本書分兩輪：

- 第一輪：複製 `<名稱>.epub`
- 第二輪：刪除第一輪的書，改複製 `<名稱>.fxl.kepub.epub`

每輪都檢查下列項目（先做 A、B、C、D，其餘視情況）：

1. **是否以固定版面開啟**：圖片沒有被重排、切割、拉伸，也沒有文字與圖片錯位。這是整個專案最大的風險（票 07 第三節），兩輪的差別是最重要的結論。
2. 翻頁方向、目錄跳轉、書櫃縮圖（A、B），與 Apple Books 的預期相同。
3. **C、D**：橫放（若該機型能旋轉）時雙頁配對與封面行為；記錄封面是否單獨、P2 與 P3 的左右。
4. **E**：書櫃縮圖是否正常（GIF 封面另外產生了 JPEG）。
5. **I**：書櫃縮圖是否是 EXTERNAL COVER。
6. **F**：WebP 頁（P2、P4）是否顯示或空白。對照 **A** 的 P7（WebP 已轉 JPEG）應該正常。
7. **G、H**：翻頁速度差別。
8. 兩輪都要記錄：書籤與筆記是否可用（`.fxl.kepub.epub` 預期停用）。
9. 記錄機型與韌體版本（設定 → 裝置資訊）。

Kobo 手機與平板 app 若方便取得測試書，也可以補測，記錄 app 版本。

## Comments

2026-11-16　使用者回報實機驗證結果（Apple Books 與 Kobo 都測過）：

- **整體：驗證都通過。** 固定版面、翻頁方向（RTL 與 LTR 都與書籍設定相同）、目錄、封面等檢查項目沒有發現問題。
- **大圖載入較慢**：G-big-pages（每頁 3000x4500，約 13.5M 像素）載入速度較慢，符合 Kobo 規格對 3,800,000 像素的建議（票 07）。處理方式是用 `--max-size`（例如 `--max-size 1950`）縮小，H-big-pages-resized 就是這個對照。
- **WebP 與 GIF 沒有太大影響**：含 WebP 的書與 GIF 封面的書都能正常閱讀。

我依「驗證都通過」勾選了清單，但回報裡**沒有**下列細節，所以沒有據此下結論，需要時請補充：

- 裝置型號與系統、韌體版本（該項保持未勾選）。
- Kobo 上純 `.epub` 與 `.fxl.kepub.epub` 的差異。回報只說都通過，沒說兩種副檔名是否都以固定版面正常開啟、是否有差異。這決定 `--help` 與說明文件對 `.fxl.kepub.epub` 的措辭要不要改。
- `--keep-webp` 的書（F）在 Kobo 上是否顯示，以及雙頁（C、D）橫放時的實際配對與封面位置。「沒有太大影響」可能是指這些都正常，但我無法確認。
