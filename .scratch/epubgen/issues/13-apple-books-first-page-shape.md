# 13: Apple Books 換頁時畫面跳動（第一頁的形狀）

**What to build:** 使用者轉換自己的書（258 頁，`--direction ltr`）後，在 Apple Books（Mac）換頁時，每一頁都先以過大的比例顯示，0.3 到 0.5 秒後才縮回正確大小，畫面跳一下。

**Blocked by:** None

**Status:** ready-for-human

- [x] 找出原因並以實機實驗證實
- [x] 第一頁與形狀接近（5% 以內）的頁面共用同一個 viewport，圖片等比例縮放置中，不重新取樣
- [x] 單頁的書、形狀差很多的頁面，維持各自的尺寸
- [x] 移除沒有效果的 `--uniform-size`
- [x] EPUBCheck 沒有錯誤（新增「square-cover」情境）
- [ ] 實機：用最新版重新轉換使用者的整本書（`device-test/user-book/F-shared-size.epub`），確認 Apple Books 換頁不再跳動

## Comments

### 調查過程

1. 逐格分析使用者的錄影（30 格每秒）：翻頁的滑動動畫結束後，頁面先以約 1.25 倍的比例顯示、底部被裁掉，0.3 到 0.5 秒後在單一一格內縮回正確大小。縮回後每一頁的高度都一致。
2. 第一個假設是「各頁尺寸略有不同」（這本書有 48 種尺寸），新增了 `--uniform-size` 讓寬高比接近的頁面共用 viewport。實機結果：**仍然會跳**。
3. 第一輪實驗（前 30 頁，SVG 包裹、Apple 傳統 metadata 與 display-options、img 屬性寫法共 5 種）：**全部都會跳**。
4. 使用者提供一本同樣由 epubgen 產生、**不會跳**的書：79 頁全部 1456x2054。會跳的書第一頁是 1523x1469（接近正方形），第二頁 1200x864（橫向），其餘大多是 1200x17xx 的直式頁面。
5. 第二輪實驗，使用者實機結果：

| 檔案 | 內容 | 結果 |
|------|------|------|
| E1 | 拿掉前 3 頁，第一頁是直式；其餘頁面仍有 14 種略有不同的尺寸 | 不會跳 |
| E2 | 同 E1，所有頁面統一尺寸 | 不會跳 |
| E3 | 保留封面，所有頁面（包括封面）統一成 1200x1738 | 不會跳 |
| E4 | 對照組，原本的前 30 頁 | 會跳 |

### 結論

Apple Books 以**第一頁**的形狀決定整本書的頁面比例。第一頁形狀不同，每次換頁都會先用錯的比例顯示再修正。其餘頁面彼此差約 2% 不會造成跳動（E1）。

### 做法

預設行為：第一頁的寬高比與其餘頁面寬高比的中位數相差超過 2% 時，第一頁的 viewport 改用其餘頁面寬度與寬高比的中位數，封面圖等比例縮放置中，旁邊留白（沒有設定底色，交給閱讀器）。不需要任何參數。

- 這偏離了 spec user story 4「每一頁的版面尺寸等於該圖片自己的像素尺寸」，但只影響第一頁，而且是為了修正每一頁都跳動的問題。
- 書櫃縮圖（cover-image）仍是原本的封面圖，不受影響。
- 置中使用絕對定位，不依賴 `object-fit`，因為 Kobo eInk 的舊版 WebKit 可能不支援。Kobo 上的表現未實測。
- `--uniform-size` 實機證實沒有效果，已移除，教學文件同步更新。
- 2% 的門檻來自 E1：E1 的第一頁 1200x1738 與其他頁面相差約 2.1%，沒有跳動。介於 2% 與 50% 之間的情況沒有實測。

### 第二次修正（只調整第一頁仍會小幅跳動）

只調整第一頁的版本（D-first-page-fixed）實機仍「稍微跳一下」。逐格分析錄影：每次換頁後約 0.3 秒，頁面從略大約 2%、底部被裁掉的狀態縮回正確大小，幅度比原本（約 1.25 倍）小很多。原因相同：Apple Books 先用第一頁的比例（1200x1718）顯示，再換成該頁自己的比例（例如 1200x1738）。E1 當時被判斷為不跳，推測是幅度太小沒被注意到；E2、E3 所有頁面尺寸一致，沒有跳。

改為：第一頁，以及寬高比與參考值相差 5% 以內的頁面，都用參考尺寸（第一頁以外頁面寬度與寬高比的中位數）。使用者的書套用後，258 頁中有 255 頁共用 1200x1718，只有第 2 頁（1200x864）、第 114 頁（960x673）、第 211 頁（1200x2342）維持自己的尺寸，這三頁換頁時仍可能跳一下。

圖片最多約有 5% 的留白（使用者這本書的頁面之間只差約 1.5%）。形狀差很多的頁面也強制共用尺寸（像 E3 那樣）雖然不會跳，但橫向頁面會被縮得很小，所以沒有這樣做。
