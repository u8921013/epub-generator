# 09: 選用的壓縮與縮放

**What to build:** 儲存空間有限的使用者可以用參數縮小 EPUB：一個參數指定重新壓縮的 JPEG 品質，一個參數把圖片縮到指定的尺寸上限（spec 的建議名稱是 `--quality` 和 `--max-size`）。這兩個處理只有在使用者給了對應參數時才執行；沒給時圖片位元組維持原樣。圖片經過處理後，該頁的 viewport 跟著處理後的圖片，不會留白或變形。

縮放維持長寬比，只縮小不放大。參數的確切語意（例如尺寸上限是長邊還是寬高各自的上限）由實作者決定，並寫進 `--help`。

排在票 08 之後，是因為兩者共用「處理後的圖片決定 viewport」這條路徑。

涵蓋 spec 的 user story 28–30。

**Blocked by:** 08

**Status:** ready-for-agent

- [x] 沒給這兩個參數時，非 WebP 圖片的位元組與原檔完全相同
- [x] 給了品質參數時，圖片被重新壓縮，輸出檔比不加參數時小
- [x] 給了尺寸上限時，超過上限的圖片被等比例縮小到上限以內
- [x] 沒超過上限的圖片不被放大
- [x] 縮放後該頁的 viewport 等於縮放後圖片的像素尺寸

- [x] 參數值不合法（例如品質超出範圍、尺寸不是正整數）時顯示用法說明並以非零結束代碼結束

## Comments

完成。語意（也寫在 `--help`）：

- `--quality 1-100`：重新壓縮。JPEG 重新編碼；PNG 轉成 JPEG（有損，使用者明確要求壓縮）；WebP 預設本來就轉 JPEG，改用這個品質，`--keep-webp` 時則重新編碼成 WebP；GIF 不受影響。壓縮後反而比原檔大的 JPEG（只重新壓縮、沒縮小）維持原檔，因為使用者要的是縮小檔案。
- `--max-size PIXELS`：長邊上限，等比例縮小、不放大、最小邊至少 1 像素。長邊剛好等於上限的圖不處理。縮小後 JPEG 維持 JPEG、PNG 維持 PNG（無損）、GIF 與預設的 WebP 轉成 JPEG（GIF 動畫只留第一個畫格，頁面不再是動畫）、保留的 WebP 維持 WebP。
- 沒給參數時，非 WebP 圖片位元組完全不變。重新編碼的圖片會先依 EXIF 轉正方向（重新編碼會丟掉 EXIF）。viewport 一律取自最終放進 EPUB 的圖片；外部 `--cover` 也會套用相同處理。
- 兩個參數的不合法值（0、負數、非整數、品質超出 1–100）都顯示用法說明。
- 修掉一個既有的潛在 bug：細節很多的大頁面以 JPEG 高品質編碼時會因為 Pillow 的 64KB 編碼緩衝區失敗（`OSError: broken data stream`）。票 08 的 WebP 轉 JPEG 原本也有這個風險（先前測試圖片太小沒踩到），現在一併修正並加回歸測試。
- Kobo 建議每頁不超過約 3,800,000 像素（約 1950x1950，票 07）。`--max-size 1950` 可作為參考值，沒有設為預設值。
- EPUBCheck 新增「quality-and-resize」與「resize-only」兩個情境，15 個情境全部通過。
