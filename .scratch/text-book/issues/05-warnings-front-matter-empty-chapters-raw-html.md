# 05: 警告機制、front matter、空章、原始 HTML

**What to build:** 建立文字書的警告機制：轉換過程中產生的警告在結束時集中列在標準錯誤，每一項包含檔名與原因；有警告但成功時結束代碼為 0。並用它處理三種情況：

- 檔案開頭的 YAML front matter（`---` 單獨一行開頭、到對應的 `---` 結束）整段略過，不出現在書裡、不當作書籍資訊。
- 略過 front matter 後沒有任何內容的 md 跳過並警告，不產生空白章；整個資料夾沒有任何有內容的章時報錯（結束代碼 1）。
- md 裡的原始 HTML（區塊與行內）轉義成純文字顯示，並對該檔案產生警告。

建書結果新增警告清單；CLI 負責把它印出。

涵蓋 spec 的 user story 27–30、59、60。

## Comments

- 2026-11-22：警告由轉譯器回傳「原因」，建書進入點加上相對於輸入資料夾的檔名（`第1部/a.md：原因`）；CLI 在成功訊息前把全部警告印到標準錯誤，標題為「有 N 則警告」。
- 原始 HTML：解析時開啟 HTML 只為了認出它，輸出一律轉義。每個檔案一則警告，列出所有出現的行號（行號從原始檔案算起，含 front matter）。多行 HTML 區塊轉義後以 `<br />` 保留換行。
- 行內 HTML 的行號以所在段落的起始行加上之前的換行數推算；換行出現在行內程式碼裡時可能略有偏差，spec 只要求「必要時附行號」，暫不處理。
- 「空」的判定是略過 front matter 後解析不出任何區塊（空白行、只有連結參考定義都算空）。
- 審查記下但未處理：警告目前是字串而非結構化型別；`_build_text_book` 職責漸多，票 07、08 加入連結與插圖時再考慮抽出單章載入。GLOSSARY 尚未收「警告」「空章」「front matter」。
