# 文字書：把 Markdown 資料夾轉成 EPUB

Status: ready-for-agent

## Problem Statement

我手上有一些以 Markdown 寫成的長篇內容，例如一部分章存放的網路小說：一個資料夾裡有幾百個 md 檔，每個檔案是一章。我想在 Apple Books 和 Kobo 上像讀一般電子書一樣閱讀它們，有目錄、文字能隨螢幕與字級重排。

`epubgen` 目前只能把圖片資料夾做成固定版面的漫畫書，遇到 md 檔會說「資料夾裡沒有可用的圖片」。手動把幾百個 md 檔轉成 EPUB 很繁瑣；一般的轉檔工具要嘛需要寫設定檔、要嘛章節順序依字典序把 `第10章` 排在 `第2章` 前面，而且常常在中文段落裡多出奇怪的空白。

## Solution

讓同一個 `epubgen` 指令也能產生**文字書**。使用者給它一個含有 Markdown 檔案的資料夾，它就產生一本可重排（reflowable）的 EPUB 3：每個 md 檔是一**章**，章名取檔案內的第一個一級標題，章節順序依檔名自然排序，第一層子資料夾成為**部**，目錄最多兩層。同一個輸出檔在 Apple Books 和 Kobo 都能正常閱讀。

書的種類由輸入資料夾的內容自動判斷（見 ADR 0001）：任何位置有 Markdown 檔就是文字書，否則照舊產生**漫畫書**。既有用法完全不變。

最簡單的用法和漫畫書一樣只需要一個參數：

```
epubgen ./pages
```

輸出 `pages.epub`，放在輸入資料夾旁邊。

## User Stories

### 判斷書的種類

1. As a 讀者, I want 用和漫畫書相同的 `epubgen <資料夾>` 指令轉換 Markdown 資料夾, so that 我不用記第二個指令或多打旗標。
2. As a 讀者, I want 資料夾裡任何位置有 `.md` 或 `.markdown` 檔時自動產生文字書, so that 工具自己知道我要哪一種書。
3. As a 讀者, I want 副檔名不分大小寫（`.MD`、`.Markdown` 也算）, so that 不同編輯器存出來的檔案都能被認得。
4. As a 漫畫讀者, I want 只有圖片的資料夾照舊產生漫畫書, so that 我原本的用法和輸出完全不受影響。
5. As a 讀者, I want 文字書資料夾裡的圖片只被當成插圖候選而不是漫畫頁, so that 我把插圖和 md 放在一起時不會被誤判或報錯。
6. As a 讀者, I want `.txt` 等其他檔案被忽略, so that 資料夾裡的雜檔不會混進書裡。

### 章與章名

7. As a 讀者, I want 每個 Markdown 檔成為一章, so that 書的結構和我的檔案一一對應。
8. As a 讀者, I want 章名取自檔案內第一個一級標題（`# 第8章 梁溪`）, so that 目錄顯示的是真正的章名而不是檔名。
9. As a 讀者, I want 檔案沒有一級標題時，章名改用去掉副檔名的檔名, so that 每一章在目錄裡都有名稱。
10. As a 讀者, I want 用檔名當章名時保留原本的數字前綴（`01-序章`）, so that 規則簡單可預期；想要乾淨的章名我就自己寫標題。
11. As a 讀者, I want 章節依檔名自然排序（`8096_2` 在 `8096_10` 前）, so that 幾百章的小說順序正確，不用把檔名補零。
12. As a 讀者, I want 一級標題同時保留在章的內文裡, so that 翻到每章開頭都看得到章名。
13. As a 讀者, I want 同一檔案裡第二個以後的一級標題照一般標題顯示, so that 內容不會因為多寫了一個標題而被切開或消失。

### 部與目錄

14. As a 讀者, I want 第一層子資料夾成為一部、資料夾名稱就是部名, so that 我用資料夾就能把章分組。
15. As a 讀者, I want 根目錄的 md 排在所有部之前、不屬於任何部, so that 序或前言可以直接放在根目錄。
16. As a 讀者, I want 部也依資料夾名稱自然排序, so that `第2部` 排在 `第10部` 前。
17. As a 讀者, I want 更深層子資料夾的 md 併入所屬的第一層部, so that 目錄最多兩層，不會深到難以瀏覽。
18. As a 讀者, I want 閱讀器的目錄能直接跳到各章開頭, so that 我可以快速找到想看的那一章。
19. As a 讀者, I want 目錄中的部能展開看到它的章, so that 長篇作品的目錄有層次。
20. As a 讀者, I want 目錄只列部和章、不列章內的小標題, so that 幾百章的目錄不會被小標淹沒。
21. As a 讀者, I want 沒有任何 md 的子資料夾不出現在目錄裡, so that 放插圖的資料夾不會變成空的部。

### Markdown 內容

22. As a 讀者, I want 段落、標題、粗體、斜體、引用、清單、分隔線照 CommonMark 呈現, so that 一般的 Markdown 寫法都能正確顯示。
23. As a 技術文件作者, I want 程式碼區塊保留縮排與換行並以等寬字顯示, so that 程式碼在閱讀器上可讀。
24. As a 技術文件作者, I want 表格與刪除線被正確呈現, so that 常用的 GFM 寫法不會變成一堆 `|` 和 `~~`。
25. As a 中文作者, I want 段落中兩個中日韓文字之間的單一換行直接相連、不多出空白, so that 我為了方便編輯而在句中換行時，書裡不會出現「很好， 我們」這種斷裂。
26. As a 作者, I want 英文等其他文字之間的單一換行照標準轉成空白, so that 英文單字不會黏在一起。
27. As a 作者, I want 檔案開頭的 YAML front matter 被略過、不出現在書裡, so that 從靜態網站搬來的 md 也能直接轉。
28. As a 作者, I want md 裡的原始 HTML 被轉義成純文字並得到警告, so that 書不會因為不合法的 XHTML 而被閱讀器拒絕開啟，而我也知道哪裡需要修改。
29. As a 讀者, I want 空的 md 檔或只有 front matter 的 md 檔被跳過並得到警告, so that 書裡不會有空白章。
30. As a 讀者, I want 資料夾裡完全沒有有內容的 md 時得到明確的錯誤, so that 我知道為什麼沒有產生書。

### 書內連結

31. As a 作者, I want `[見第二章](02.md)` 轉成跳到該章開頭的書內連結, so that 我在 md 之間寫的交叉參照在書裡也能點。
32. As a 作者, I want `[](02.md#某標題)` 跳到該章的那個標題, so that 我可以連到章內的特定段落。
33. As a 作者, I want 同一檔案內的 `[](#某標題)` 也能跳轉, so that 章內的目錄或前後參照能用。
34. As a 作者, I want 標題的錨點名稱和 GitHub 預覽產生的一致（小寫、去標點、空白換成 `-`、保留中文、重複標題加 `-1`、`-2`）, so that 我在 GitHub 或 VS Code 預覽時寫好的連結轉成書後不會失效。
35. As a 作者, I want 連到不存在的檔案或標題時保留連結文字並得到警告, so that 失效連結不會讓書壞掉，我也知道要修哪裡。
36. As a 讀者, I want `https://` 等外部連結維持原樣, so that 我可以在閱讀器裡開網頁。

### 插圖

37. As a 作者, I want `![](images/a.png)` 引用的本地圖片被打包進書裡並顯示在原位置, so that 插圖跟著文字出現。
38. As a 作者, I want 插圖支援 JPEG、PNG、GIF、WebP, so that 和漫畫書支援的格式一致。
39. As a 作者, I want 可以引用輸入資料夾以外的圖片（`../shared/logo.png`）, so that 多本書共用的圖片不用複製。
40. As a 作者, I want 多個章引用同一張圖片時書裡只存一份, so that 檔案不會無謂地變大。
41. As a 讀者, I want 沒被任何 md 引用的圖片不打包, so that 資料夾裡的草稿圖不會塞進書裡。
42. As a 作者, I want 網路圖片（`https://…`）不被下載，改成顯示替代文字並得到警告, so that 轉換不需要網路，我也知道哪些圖沒進書。
43. As a 作者, I want SVG 或其他不支援格式的插圖顯示替代文字並得到警告, so that 書仍然能產生。
44. As a 作者, I want 找不到或損毀的插圖預設讓轉換失敗並告訴我是哪一張, so that 我不會在不知情下得到缺圖的書。
45. As a 作者, I want 加上 `--skip-broken` 時跳過找不到或損毀的插圖並在結束時列出, so that 我可以先拿到一本能讀的書。
46. As a 作者, I want 插圖在閱讀器上不超出螢幕寬度, so that 大圖不會被裁掉或需要橫向捲動。
47. As a 作者, I want `--quality`、`--max-size`、`--keep-webp` 套用在插圖上，規則和漫畫書相同, so that 我可以用熟悉的旗標控制檔案大小。

### 封面與書籍資訊

48. As a 讀者, I want 書名預設為資料夾名稱，`--title` 可以覆寫, so that 和漫畫書行為一致。
49. As a 讀者, I want `--author`、`--language` 寫入書籍資訊，語言預設 `zh-TW`, so that 閱讀器顯示正確的作者並使用合適的斷行與字型。
50. As a 讀者, I want 用 `--cover` 指定封面圖片時，它成為書架上的縮圖, so that 我在書架上認得出這本書。
51. As a 讀者, I want 指定封面時書的最前面多一頁封面頁, so that 開書的第一個畫面是封面，像一般電子書一樣。
52. As a 讀者, I want 封面頁不出現在目錄裡, so that 目錄只有內容。
53. As a 讀者, I want 沒有指定封面時書就沒有封面圖, so that 結果可預期，閱讀器自己顯示預設縮圖。
54. As a 讀者, I want 不需要寫 front matter 或設定檔就能設定書籍資訊, so that 所有設定都在指令列上一目了然。

### 旗標

55. As a 讀者, I want 對文字書使用 `--direction` 或 `--spread` 時得到明確的錯誤, so that 我知道這些旗標只對漫畫書有效，而不是默默被忽略。
56. As a 讀者, I want `-o`、`--force` 對文字書的行為和漫畫書相同, so that 輸出路徑與覆蓋規則只需要學一次。
57. As a 讀者, I want `epubgen --help` 說明工具也能轉換 Markdown 資料夾，並註明哪些旗標只對漫畫書有效, so that 我不用讀原始碼就知道怎麼用。

### 輸出、警告與錯誤

58. As a 讀者, I want 成功時看到輸出路徑與章數, so that 我知道書產生在哪、內容是否齊全。
59. As a 作者, I want 所有警告在轉換結束時集中列出，每一項都有檔名與原因, so that 我能一次看完要修的地方。
60. As a 作者, I want 有警告但轉換成功時結束代碼是 0, so that 在腳本裡警告不會被當成失敗。
61. As a 作者, I want 只有真正的錯誤才回傳非 0 的結束代碼, so that 腳本能正確判斷成敗。
62. As a 讀者, I want 轉換失敗時不留下半成品，輸入資料夾也不被修改, so that 失敗不會造成任何副作用。

### 閱讀體驗與相容性

63. As a 讀者, I want 文字能隨閱讀器的字級、字型與螢幕大小重排, so that 我能用自己習慣的設定閱讀。
64. As a 讀者, I want 書由左到右翻頁、文字橫排, so that 和一般中文橫排電子書一致。
65. As a 讀者, I want 書使用簡單的內建樣式（段落間距、標題、程式碼區塊、表格框線）而不嵌入字型, so that 閱讀器的字型設定能生效、檔案也小。
66. As a 讀者, I want 同一個 `.epub` 在 Apple Books 與 Kobo 都能開啟並正確顯示目錄, so that 我只需要產生一次。
67. As a 讀者, I want 產生的 EPUB 通過 EPUBCheck, so that 嚴格的閱讀器也不會拒絕它。
68. As a 讀者, I want 幾百章、數 MB 文字的書也能順利轉換, so that 長篇小說不會遇到問題。

## Implementation Decisions

### 技術選型

- 新增一個 Markdown 解析套件作為執行期依賴：`markdown-it-py`，以 CommonMark 為基礎並啟用表格與刪除線。不啟用需要額外依賴的擴充（例如自動連結化）。這是專案第二個執行期依賴（第一個是 Pillow）。
- 不自己寫 Markdown 解析器；軟換行、原始 HTML、錨點、連結與圖片的特殊處理都透過自訂該套件的轉譯規則或走訪其 token 完成。
- 標題錨點名稱的產生規則（GitHub 風格）自行實作，不額外引入外掛套件，除非實作時發現現成外掛的規則與 GitHub 完全一致。

### 模組劃分

沿用現有「掃描 → 載入 → 組裝 → 寫出」的分層，文字書新增或擴充以下模組：

- **書的種類判斷**：給定輸入資料夾，判斷是文字書還是漫畫書。規則：遞迴搜尋，任何位置有 Markdown 檔（副檔名不分大小寫的 `.md` / `.markdown`）就是文字書。判斷結果決定之後走哪一條流程。
- **文字書掃描**：讀取資料夾，產出「書 → 部 → 章」結構。根目錄的 md 是不屬於任何部的章，排在最前；每個含 md 的第一層子資料夾成為一部，其內（含更深層）的 md 依相對路徑自然排序成為該部的章。沿用漫畫書掃描的自然排序規則。
- **Markdown 轉譯（第二接縫）**：純函式，不碰檔案系統。輸入一個檔案的 Markdown 文字，以及一個由呼叫端提供的「目標解析」介面；輸出一個轉譯結果，包含：
  - 章名（第一個一級標題的純文字；沒有則為空，由呼叫端退回檔名）；
  - 這一章的 XHTML 內文片段；
  - 這一章所有標題的錨點名稱；
  - 這一章引用的插圖與連結目標；
  - 警告清單（原始 HTML、無法使用的插圖、失效連結等）；
  - 內容是否為空（略過 front matter 後沒有任何內容）。

  「目標解析」介面讓轉譯器把 md 裡的相對路徑（連結的檔案與錨點、插圖路徑）換成書內的 href，或回報找不到。測試時傳入假的解析器即可，不需要建立檔案。跨章錨點的驗證需要先知道所有章的錨點，因此組裝流程先取得每章的錨點，再完成連結解析（兩階段，或先收集標題再轉譯，由實作決定）。
- **插圖載入**：重用現有的圖片載入與處理（WebP 轉 JPEG、`--quality`、`--max-size`、損毀判斷），對象從「漫畫頁」換成「被引用的插圖」。同一個來源檔案只載入、打包一次。
- **EPUB 組裝**：新增 reflowable 版本的組裝，與現有 fixed layout 組裝共用 container、package 的共通部分（metadata、manifest、zip 打包、`mimetype` 放第一個且不壓縮）。差異：不宣告 pre-paginated、不產生 viewport；spine 方向 `ltr`；navigation document 支援兩層（部 → 章）；加入一份內建 CSS；指定封面時加入封面頁與封面圖。
- **建書進入點**：既有的建書函式依書的種類分流。選項驗證依種類不同：文字書拒絕 `--direction`（非預設值）與 `--spread`。建書結果新增警告清單（文字書使用）；現有的 `skipped` 欄位維持，`--skip-broken` 跳過的插圖記錄在那裡。
- **CLI**：位置參數說明改為「放滿圖片或 Markdown 檔的資料夾」；說明文字註明 `--direction`、`--spread` 只對漫畫書有效。成功訊息依種類顯示「共 N 頁」或「共 N 章」。警告與跳過清單在結束時印到標準錯誤。

### 判斷 `--direction` 是否被使用

`--direction` 目前預設值是 `rtl`，CLI 無法區分「使用者沒給」與「使用者給了 rtl」。實作時把 CLI 層的預設值改成「未指定」，由建書進入點依書的種類套用預設（漫畫書 `rtl`）；文字書收到任何明確的 `--direction` 都報錯。漫畫書的行為與輸出不得改變。

### CLI 介面

文字書可用的參數：

- 位置參數：輸入資料夾。
- `-o` / `--force`：與漫畫書相同。預設輸出為輸入資料夾同層的 `<書名>.epub`。
- `--title`、`--author`、`--language`：與漫畫書相同。
- `--cover`：指定封面圖片；可以在輸入資料夾內或外。沒指定就沒有封面。
- `--skip-broken`：跳過找不到或損毀的插圖。
- `--keep-webp`、`--quality`、`--max-size`：套用在插圖上，規則與漫畫書相同。
- `--direction`、`--spread`：錯誤，訊息說明這些旗標只對漫畫書有效。

### EPUB 結構

- EPUB 3，reflowable（不設定 `rendition:layout`，或明確為 `reflowable`）。
- 每章一個 XHTML 文件，檔名由程式產生（與來源檔名無關，避免特殊字元問題）；部不產生獨立文件。
- navigation document：根目錄的章是第一層項目；每部是第一層項目，其章是第二層項目。部的項目指向該部第一章。封面頁不在目錄中。
- 指定封面時：封面圖片在 manifest 標記為 `cover-image`；spine 最前面是一個只放封面圖的 XHTML 頁。
- 一份內建 CSS：段落間距、標題、程式碼區塊（等寬、保留空白、可換行或捲動）、表格框線、圖片最大寬度 100%。不嵌入字型，不指定字型家族以外的強制樣式，讓閱讀器設定生效。
- `dc:language` 寫入 `--language`；spine `page-progression-direction` 為 `ltr`。

### 輸入規則

- 書的種類：見 ADR 0001。
- 章名：第一個一級標題的純文字（去掉行內格式）；沒有則用去掉副檔名的檔名，不去數字前綴。
- 排序：部與章都依名稱自然排序（沿用漫畫書規則）。
- 前置 YAML front matter：檔案以 `---` 單獨一行開頭、之後有對應的 `---` 結束行時，整段略過；不作為元資料讀取。
- 空章：略過 front matter 後沒有任何內容的檔案跳過並警告；沒有任何有內容的章時報錯。
- 被忽略的檔案：非 Markdown、非被引用圖片的所有檔案，包括隱藏檔（如 `.DS_Store`）。

### 轉譯規則

- 支援：CommonMark 全部語法、表格、刪除線。
- 軟換行：前一個字元與後一個字元都是中日韓文字或全形標點時，直接相連；否則照標準輸出空白。
- 原始 HTML（區塊與行內）：轉義成純文字顯示，每個檔案產生一則警告（指出檔名，必要時附行號）。
- 標題錨點：GitHub 風格；同一章內重複的名稱依序加 `-1`、`-2`。
- 連結：
  - 指向 Markdown 檔（相對路徑，可帶 `#錨點`）→ 換成書內對應章 XHTML 的 href；找不到檔案或錨點 → 輸出純文字並警告。
  - 只有 `#錨點` → 同章內跳轉；找不到 → 純文字並警告。
  - 外部 URL（有 scheme）→ 原樣保留。
  - 其他相對路徑（指向非 Markdown 檔）→ 純文字並警告。
- 插圖：
  - 相對或絕對本地路徑，副檔名為 JPEG / PNG / GIF / WebP → 打包並換成書內 href；路徑以 md 檔所在資料夾為基準解析。
  - 網路 URL、SVG、其他格式 → 輸出替代文字並警告。
  - 檔案不存在或損毀 → 預設錯誤；`--skip-broken` 時輸出替代文字並記錄在跳過清單。
- 所有輸出都必須是格式正確的 XHTML。

### 錯誤處理

錯誤（結束代碼 1，不產生輸出檔）：

- 沿用漫畫書的輸入路徑、輸出路徑、覆蓋、參數值錯誤。
- 文字書使用 `--direction` 或 `--spread`。
- 沒有任何有內容的章。
- 插圖找不到或損毀，且沒有 `--skip-broken`（訊息提示可加 `--skip-broken`）。
- `--cover` 指定的檔案不存在、不是支援的圖片或無法讀取。

警告（結束代碼 0，結束時集中列在標準錯誤）：

- 空章被跳過。
- 原始 HTML 被轉義。
- 網路圖片、SVG 或其他不支援格式的插圖。
- 失效的書內連結或錨點。

## Testing Decisions

### 什麼是好的測試

只測外部觀察得到的行為。主接縫測使用者看得到的：結束代碼、輸出訊息、輸出檔，以及把 EPUB 當 zip 解開後的內容。第二接縫只測轉譯結果的內容（章名、XHTML 片段、錨點、警告），不測它內部怎麼使用解析套件。這樣掃描、轉譯、組裝都可以自由重構而不用改測試。

### 測試接縫

兩個接縫：

1. **CLI 進入點（主接縫）**：與漫畫書測試相同，在同一個行程內以參數列表呼叫進入函式。測試在暫存資料夾即時寫出小型 md 檔與插圖（插圖沿用現有的即時產生圖片工具），不把任何真實書籍內容放進版本控制。觀察方式沿用現有的 EPUB 解析輔助工具，並擴充：讀出某一章的文字與 XHTML、讀出兩層目錄（名稱、層級、目標章）、讀出某個書內連結的目標、列出打包的插圖。
2. **Markdown 轉譯（第二接縫）**：直接以 Markdown 文字與假的目標解析器呼叫轉譯函式，斷言轉譯結果。用於規則細、組合多的轉譯行為。

### 主接縫要涵蓋的情境

- 只有 md 的資料夾產生 reflowable EPUB，章數與 md 數相同；只有圖片的資料夾照舊產生漫畫書（既有測試全部維持通過）。
- md 與圖片並存（包括都在根目錄）時產生文字書，未被引用的圖片不在書裡。
- `.MD`、`.markdown` 被認得；`.txt`、`.DS_Store` 被忽略。
- 章依檔名自然排序（`x_2` 在 `x_10` 前）；章名取一級標題，沒有時取檔名（保留數字前綴）。
- 部：根目錄的章在前、部依名稱排序、更深層併入第一層部、目錄兩層且部指向其第一章；只放圖片的子資料夾不成為部。
- 書內連結指到正確的章與錨點；失效連結變成純文字並產生警告。
- 插圖被打包並在章內引用；同一張圖只打包一次；資料夾外的插圖可用；`--quality` / `--max-size` / `--keep-webp` 對插圖生效。
- 缺少或損毀的插圖：預設錯誤、`--skip-broken` 時跳過並列出。
- 網路圖片、SVG 產生警告與替代文字。
- 空章被跳過並警告；全部為空時報錯。
- `--cover`：有封面圖與封面頁、封面頁不在目錄；沒指定時沒有封面。
- `--title`、`--author`、`--language` 寫入 metadata；預設輸出路徑與 `-o`、`--force`。
- `--direction`、`--spread` 對文字書報錯；漫畫書不帶 `--direction` 時預設仍是 RTL。
- 有警告時結束代碼為 0，警告列在標準錯誤；錯誤時結束代碼為 1、不留下輸出檔、輸入資料夾不變。

### 第二接縫要涵蓋的情境

- 章名：第一個一級標題的純文字（含行內格式時去除格式）；沒有一級標題時為空；第二個一級標題照常輸出。
- 中日韓軟換行相連、英文軟換行為空白、中英交界的處理符合規則。
- 原始 HTML 被轉義並產生警告。
- 表格、刪除線、程式碼區塊、引用、清單的輸出。
- front matter 被略過；只有 front matter 時回報內容為空。
- 錨點名稱：英文、中文、標點、重複標題。
- 連結與插圖目標交給解析器，解析失敗時輸出純文字或替代文字並產生警告；外部連結原樣保留。
- 輸出為格式正確的 XHTML（可用 XML 解析器解析）。

### EPUBCheck

在現有的 EPUBCheck 情境表加入文字書情境：最簡單的文字書、有部有章與書內連結、有插圖與封面、含表格與程式碼區塊。要求沒有錯誤。環境沒有 Java 或 EPUBCheck 時照舊自動跳過。

### 手動驗證

在實機測試書產生腳本中加入一本文字書範本，涵蓋：有部有章、中文軟換行、表格、程式碼區塊、插圖、書內連結、封面頁。每次改動文字書的 EPUB 結構後，在 Apple Books 與 Kobo 各開一次，確認文字重排、目錄兩層可跳轉、書內連結、插圖不超出螢幕、封面縮圖與封面頁。另外用使用者手上那本 234 章的小說資料夾做一次真實驗收（只在本機，不進版本控制）。

### 既有範例

- 主接縫：現有的章節、封面、錯誤、輸出路徑測試，以及 EPUB 解析輔助工具與即時產生圖片的工具。
- EPUBCheck：現有的情境表與自動跳過機制。

## Out of Scope

- 直排文字與由右到左翻頁的文字書。
- 讀取 YAML front matter 作為書籍資訊；任何設定檔。
- 自訂 CSS（`--css`）與嵌入字型。
- 程式碼語法上色。
- 腳註、數學公式、Mermaid 與其他 CommonMark / 表格 / 刪除線以外的擴充語法。
- 原始 HTML 的放行或修正。
- 下載網路圖片；SVG 插圖。
- 自動產生文字封面；自動採用資料夾內的 `cover.jpg`。
- 目錄列出章內小標題；超過兩層的目錄。
- 自動去除檔名的數字前綴。
- Kobo 專用的 `.kepub.epub` 或其他平台格式。
- 同一本書混合漫畫頁與文字章。
- 清理來源內容（例如網頁抓取留下的重複標題），這屬於產生 md 的工具的責任。

## Further Notes

### 實作前需要查證

- GitHub 標題錨點名稱的確切規則（哪些標點被移除、全形標點與 emoji 的處理），要對照 GitHub 的實際行為或其公開的實作，不能憑印象寫。
- Kobo 對 reflowable EPUB 中兩層 navigation document 的顯示方式，實機確認。
- 「中日韓文字與全形標點」的字元範圍定義，實作時明確列出所用的 Unicode 區段並在測試中涵蓋邊界。

### 需求討論沒有涵蓋、建議的預設做法

- **章的 XHTML 檔名**：依閱讀順序編號，不使用來源檔名。
- **部在目錄中的連結目標**：指向該部第一章。
- **連結到非 Markdown 的本地檔案**（例如 PDF）：當作失效連結處理（純文字 + 警告）。
- **插圖替代文字為空時**：顯示檔名作為替代文字，讓讀者知道這裡原本有圖。
- **警告的數量很多時**：照樣全部列出；不做摘要或截斷。

### 使用者的實際輸入

觸發這個需求的是一個 234 個 md 檔的小說資料夾：檔名形如 `8096_1.md` 到 `8096_234.md`，每個檔案有一個一級標題與以空行分隔的段落，沒有 front matter、HTML、圖片或連結。它只用到最基本的路徑（每檔一章、章名取標題、自然排序），所以第一張可交付的 ticket 應該先讓這本書能轉換。
