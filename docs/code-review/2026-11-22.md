# Code Review：`text-book-spec` 分支（PR #1）

- **審查日期**：2026-11-22
- **審查範圍**：`git diff main...text-book-spec`（共 15 個 commit）
- **整體評估**：架構與模組切分清楚、兩條測試接縫（CLI 主接縫與 Markdown 純函式第二接縫）設計紮實、spec 與 Out of Scope 邊界守得很嚴格，既有漫畫書路徑未受破壞。以下依嚴重程度列出待修與改善項目。

---

## 必須修

### 1. 連結或插圖路徑含 `%00` 會引發未捕獲的 `ValueError` 崩潰
- **位置**：`src/epubgen/targets.py:43,52`、`src/epubgen/illustrations.py:26`
- **問題描述**：`src/epubgen/markdown.py:183` 與 `src/epubgen/markdown.py:277` 會先對連結與圖片目標執行 `unquote()`，再傳入 `ChapterTargets.link` 與 `Illustrations.href` 呼叫 `Path.resolve()`。若目標含有 NUL 位元組，會直接拋出未捕獲的 `ValueError: embedded null byte`，繞過 `EpubgenError` 錯誤處理並印出 traceback。
- **觸發輸入**：Markdown 內含 `[x](a%00b.md)` 或 `![圖](a%00b.png)`。
- **建議修法**：在解析路徑前檢查 `"\x00" in target` 或在 `Path.resolve()` 外攔截 `(ValueError, OSError)`：連結回傳 `None`（走既有失效連結警告流程），插圖視為找不到檔案（走既有缺圖錯誤／`--skip-broken` 流程）。

### 2. 中文軟換行在共用標點跨行內格式標記時會失效
- **位置**：`src/epubgen/markdown.py:125-137`
- **問題描述**：`_neighbor_text` 一看到第一個非空的 `text` / `code_inline` token 就立刻 `return`。當軟換行旁的中西文共用標點（`“”‘’…—·`）與後續中文字分屬不同 token（例如引號在粗體外面）時，`_is_cjk_side` 越過共用標點後字串就結束並回傳 `False`，導致中文段落仍多出換行／空白（違反 spec 越過共用標點且跳過格式標記的規則）。
- **觸發輸入**：
  - `中文\n“**引號**”` → 產出 `<p>中文\n“<strong>引號</strong>”</p>`（未相連）
  - `他說“**好。**”\n“走吧”` → 產出 `<p>他說“<strong>好。</strong>”\n“走吧”</p>`（未相連）
- **建議修法**：讓 `_neighbor_text` 持續跳過 `nesting != 0` 的格式標記並串接相鄰的 `text` / `code_inline` 內容（直到碰到 `image`、`html_inline`、`hardbreak` 等非文字 token 才停止），再交給 `_is_cjk_side` 判斷。

### 3. `is_text_book` 與 `scan_text_book` 對符號連結的行為不一致
- **位置**：`src/epubgen/scan.py:86-95`、`src/epubgen/scan.py:134-136`
- **問題描述**：
  1. `is_text_book` 沒有檢查 `(Path(root) / name).is_file()`，但 `scan_text_book` 與 `_markdown_under` 都有檢查。
  2. `is_text_book` 使用 `os.walk(folder)`（預設 `followlinks=False`），不會走進 symlink 子資料夾；但 `scan_text_book` 第一層使用 `folder.iterdir()` 搭配 `p.is_dir()`，會把 symlink 子資料夾當成一部掃進來。
- **觸發情境**：
  - 漫畫資料夾裡有一個壞掉的符號連結 `broken.md`：`is_text_book` 回傳 `True`（誤判為文字書），接著 `scan_text_book` 掃不到任何檔而報錯「資料夾裡沒有任何有內容的章」。
  - 資料夾根目錄沒有 `.md`，只有指向外部目錄的符號連結 `part1 -> /other/dir`（內含 `.md`）：`is_text_book` 回傳 `False`（誤判為漫畫書），但若根目錄多放一個 `.md`，`scan_text_book` 又會把 `part1` 掃成一部。
- **建議修法**：
  - 在 `is_text_book` 補上 `(Path(root) / name).is_file()`。
  - 明確統一是否跟隨 symlink 子資料夾（若比照 `os.walk` 不跟隨，在 `scan_text_book` 改為 `p.is_dir() and not p.is_symlink()`）。

### 4. 輸入含 XML 1.0 非法控制字元時會產出不合法的 XHTML
- **位置**：`src/epubgen/markdown.py:168`
- **問題描述**：`markdown-it-py` 只會替換 `\x00`，不會移除其他 XML 1.0 禁止的控制字元（`\x01`–`\x08`、`\x0b`、`\x0c`、`\x0e`–`\x1f`）。網路小說或從 PDF/網頁複製的 `.md` 偶爾會夾帶 `\x0b`（垂直定位）或 `\x0c`（換頁），這些字元會原樣寫進章 XHTML，導致 XML 解析器與 EPUBCheck 報錯、閱讀器無法開啟（違反 spec「所有輸出都必須是格式正確的 XHTML」）。
- **觸發輸入**：Markdown 內文含 `"hello \x0b world\n"`。
- **建議修法**：在 `render_markdown` 進入解析前（或寫入 XHTML 前）將 XML 1.0 禁止的控制字元替換為 `\ufffd` 或移除（保留 `\t`、`\n`、`\r`）。

## 建議修

### 5. 多行 Setext 標題的錨點遺漏軟換行空白
- **位置**：`src/epubgen/markdown.py:238-240`
- **問題描述**：`_anchor_text` 只串接 `text` 與 `code_inline`，忽略了 `softbreak` / `hardbreak`。因此多行英文 Setext 標題在目錄文字中有空白，但產生的錨點卻把兩行黏在一起，與 GitHub 規則不符。
- **觸發輸入**：`Hello\nWorld\n=====\n` → 章名為 `Hello World`，但錨點變成 `helloworld`（預期應為 `hello-world`）。
- **建議修法**：比照 `_plain_text`，在 `_anchor_text` 中將非相連的 `softbreak` 與 `hardbreak` 轉成 `" "`（已相連的 CJK `softbreak` 則不補空白）。

### 6. 一級標題含圖片且 alt 有行內格式時，章名殘留 Markdown 語法
- **位置**：`src/epubgen/markdown.py:298-308`
- **問題描述**：`_plain_text` 遇到 `child.type == "image"` 時直接取 `child.content`，在 `markdown-it-py` 裡那是未去格式的原始文字，導致目錄章名殘留 `**` 等標記（但同一個標題在內文 `<img alt="...">` 中已去掉格式）。
- **觸發輸入**：`# 章 ![**粗**圖](a.png)` → `result.title` 為 `'章 **粗**圖'`（預期應為 `'章 粗圖'`）。
- **建議修法**：在 `_plain_text` 中，遇到 `child.type == "image"` 時改為遞迴呼叫 `_plain_text(child)`（若 `child.children` 為空再退回 `child.content`）。

### 7. 先 `unquote` 再切 `#`，導致檔名含 `#`（`%23`）的連結失效
- **位置**：`src/epubgen/markdown.py:277`、`src/epubgen/targets.py:39`
- **問題描述**：`markdown.py` 先對整段 `href` 執行 `unquote()`，再交給 `ChapterTargets.link` 用 `partition("#")` 分離路徑與錨點。若檔名本身含 `#` 並以 `%23` 編碼，還原後的 `#` 會被誤判為錨點分隔符。
- **觸發輸入**：檔案為 `C#.md`，連結寫 `[C#](C%23.md)` → 被切為 `path="C"`、`fragment=".md"` 而判定失效。
- **建議修法**：改為先用 `#` 拆分 `href` 為 path 與 fragment，再分別 `unquote`（或在 `TargetResolver.link` 介面／`ChapterTargets.link` 內先 `partition("#")` 再各自 `unquote`）。

### 8. `--cover` 的 `--help` 說明未區分文字書預設無封面
- **位置**：`src/epubgen/cli.py:89-91`（以及 `src/epubgen/cli.py:77`）
- **問題描述**：`--cover` 的說明文字仍寫 `（預設：第一頁）`，與文字書「沒有指定就沒有封面、也沒有頁的概念」（spec / `GLOSSARY.md`）矛盾，容易誤導文字書使用者。另外 `--skip-broken` 僅寫「遇到損毀圖片」，在文字書情境下也涵蓋「找不到插圖」。
- **建議修法**：`--cover` 說明改為 `（漫畫書預設：第一頁；文字書預設：無封面）`；`--skip-broken` 補上「找不到或損毀的圖片」。

### 9. 章檔名編號重複計算與 GIF 封面轉檔邏輯重複
- **位置**：`src/epubgen/__init__.py:128-131`、`src/epubgen/__init__.py:191-192,229`、`src/epubgen/epub.py:307-310,343-345`
- **問題描述**：
  - 章 XHTML 檔名 `chapter_file_name(i)` 在 `_build_text_book`（建立 `BookTargets`）與 `write_text_epub`（寫 OPF、TOC、zip）兩處各自以 `enumerate(..., start=1)` 推算，靠隱式順序約定維持一致。
  - GIF 封面轉 JPEG 的判斷（`extension == ".gif"` → `cover_as_jpeg`）在 `_resolve_cover` 與 `_text_book_cover` 各寫了一次。
- **建議修法**：讓 `TextChapter` 直接攜帶 `file_name`（在 `_build_text_book` 產生一次，同時傳給 `BookTargets` 與 `write_text_epub`）；將 GIF 封面轉換抽出成 `images.py` 的共用函式，減少漫畫書與文字書的重複。

## 小問題

### 10. 圖片替代文字內的原始 HTML 不會發出警告
- **位置**：`src/epubgen/markdown.py:257-261`
- **問題描述**：`_inline_children_with_lines` 只走訪 `inline.children` 第一層，未走訪 `image.children`。
- **觸發輸入**：`![圖 <b>x</b>](a.png)`。產出 `<img ... alt="圖 &lt;b&gt;x&lt;/b&gt;" />` 仍是合法 XHTML，但不會產生原始 HTML 警告。
- **建議修法**：若希望與一般行內 HTML 行為一致，可在 `_raw_html_lines` 中一併檢查 `image.children`。

### 11. 標題含原始 HTML 時，目錄章名與內文顯示略有差異
- **位置**：`src/epubgen/markdown.py:298-308`
- **問題描述**：輸入 `# 章 <span>內</span>` 時，內文轉義顯示為 `章 <span>內</span>`，但 `_plain_text` 略過 `html_inline`，使目錄章名為 `章 內`。影響極小，可維持現狀或視需求將 `html_inline` 加入 `_plain_text`。

### 12. 封面頁 CSS 使用 `max-height: 100vh`（推測：Kobo `.epub` 相容性風險）
- **位置**：`src/epubgen/epub.py:262`
- **問題描述（推測）**：Kobo 側載純 `.epub` 時使用 Adobe RMSDK 引擎（非 WebKit），RMSDK 對 CSS `vh` 單位支援有限，可能忽略 `max-height: 100vh` 導致細長封面圖在封面頁跨頁。
- **建議修法**：待票 10 的 Kobo 實機驗收時特別確認封面頁縮放；若確實溢頁，可再評估改用 `svg` 包裝封面圖或相容的百分比寫法。

## 測試覆蓋缺口彙整

既有測試（`tests/test_text_book.py`、`tests/test_markdown.py`、`tests/test_epubcheck.py`）已涵蓋大量非 happy path 與邊界情境，建議再補齊以下幾項：

- **書種判斷**：根目錄只有圖片、子資料夾才有 `.md`（驗證仍判為文字書且根目錄圖片不打包）；壞掉的 `.md` symlink 與 symlink 子資料夾。
- **部與空章**：某個第一層子資料夾底下的所有 `.md` 都是空章時，確認該部不出現在目錄。
- **中文軟換行**：共用標點跨行內格式標記（如 `中文\n“**引號**”`、`他說“**好。**”\n“走吧”`）。
- **書內連結（主接縫）**：在 `tests/test_text_book.py` 補上含空白／`%20` 編碼檔名、含 `%23` 檔名、帶 `?query` 的本地連結，以及含 `%00` 的異常目標。
- **XHTML 合法性**：含非法 XML 控制字元（如 `\x0b`）的 Markdown 轉譯結果仍可通過 XML 解析。
