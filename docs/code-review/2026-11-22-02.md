### 小問題

#### 1. 同一條無法 `resolve()` 的壞插圖路徑被引用多次時，`--skip-broken` 會重複記錄
- **位置**：`src/epubgen/illustrations.py:25-29`
- **問題描述**：一般找不到的插圖會以 `key = path.resolve()` 快取在 `self._href_of`，多處引用時只記錄一次在 `skipped`（見票 08 Comments）。但在 `path.resolve()` 拋出 `(OSError, ValueError)` 時直接回傳 `self._unusable(...)` 而未快取，導致同一條無效路徑被重複列入 `skipped`。
- **觸發輸入**：`![圖1](a%00b.png) ![圖2](a%00b.png)` 搭配 `--skip-broken` → `result.skipped` 為 `('a.md：a\x00b.png', 'a.md：a\x00b.png')`（重複兩次）。
- **建議修法**：可用原始 `path`（或 `str(path)`）作為 fallback key 存進 `self._href_of`（例如 `self._href_of[path] = self._unusable(...)`），讓去重行為與一般缺圖一致。

#### 2. 巢狀圖片 alt 內的原始 HTML 不會發出警告
- **位置**：`src/epubgen/markdown.py:267-270`
- **問題描述**：`_raw_html_lines` 對 `image.children` 只展開一層，若圖片替代文字裡又巢狀包了一張圖片且內層 alt 含原始 HTML，不會產生原始 HTML 警告（不過輸出的 XHTML 仍是合法的）。
- **觸發輸入**：`![外 ![內 <b>x</b>](b.png)](a.png)` → `warnings == ()`。
- **建議修法**：屬極端罕見語法，可維持現狀；若要完全一致，改以遞迴 helper 走訪 `token.children`。

### 3. 評估 `TargetResolver.link(path, fragment)` 介面變更與第二接縫精神
- **評估**：不構成違背 spec 第二接縫精神。spec 的精神是「不測轉譯器內部怎麼用解析套件，內部重構不用改測試」，而 `TargetResolver` 本身就是第二接縫的公開輸入契約；原本的 `link(target)` 在傳遞已 `unquote` 的字串時已遺失「原始 `#` 與 `%23`」的語意區分，屬於契約本身有缺陷，修改契約並同步更新測試假解析器是合理的。
- **不改介面的替代做法**：維持 `link(target: str)`，讓 `markdown.py` 直接傳入未 `unquote` 的原始 `href`，由 `ChapterTargets.link` 自行先 `partition("#")` 再分別 `unquote`；缺點是 `image(target)` 收已解碼路徑而 `link(target)` 收未解碼 URI，介面語意不對稱。相比之下，現行的 `link(path, fragment)` 職責切分更清楚（URI 解析留在 `markdown.py`，檔名與錨點查找在 `targets.py`），建議維持現行設計。
