# epubgen 使用教學

`epubgen` 把一個放滿圖片的資料夾，轉成可以在 Apple Books 和 Kobo 上閱讀的漫畫 EPUB。每張圖片是獨立的一頁，圖片不會被重排、切割或變形，翻頁方向和章節目錄都可以設定。

## 1. 安裝

需要 Python 3.10 以上。建議用 [pipx](https://pipx.pypa.io/) 安裝，這樣在任何目錄都能直接輸入 `epubgen`：

```bash
cd epub-generator
pipx install .
```

沒有 pipx 的話，macOS 可以先用 Homebrew 安裝：

```bash
brew install pipx
pipx ensurepath
```

`pipx ensurepath` 之後要重新開一個終端機視窗，指令才會生效。

確認安裝成功：

```bash
epubgen --version
```

之後更新程式碼，重新安裝即可：

```bash
pipx install --force .
```

## 2. 三十秒上手

假設你有一個資料夾 `my-comic`，裡面是依序命名的圖片：

```
my-comic/
├── 1.jpg
├── 2.jpg
├── 3.jpg
└── ...
```

執行：

```bash
epubgen ./my-comic
```

成功時會看到輸出檔的路徑和頁數：

```
已輸出：/Users/你/Comics/my-comic.epub（共 24 頁）
```

輸出檔 `my-comic.epub` 放在 **輸入資料夾的旁邊**（也就是 `my-comic` 的上一層），輸入資料夾本身完全不會被修改。

預設的設定是日漫習慣：**從右到左翻頁**、每頁單獨顯示、第一張圖當封面、書名取自資料夾名稱。

## 3. 資料夾怎麼擺

### 單一資料夾：整個資料夾是一本書

```
my-comic/
├── 1.jpg
├── 2.jpg
└── 10.jpg
```

頁面依檔名**自然排序**，所以 `2.jpg` 會排在 `10.jpg` 前面，檔名不用補零。

### 有子資料夾：每個子資料夾是一章

```
my-comic/
├── cover.jpg            ← 根目錄的圖片：排在最前面，不屬於任何章節
├── 第 1 話/
│   ├── 1.jpg
│   └── 2.jpg
├── 第 2 話/
│   └── 1.jpg
└── 第 10 話/
    └── 1.jpg
```

- 章節依子資料夾名稱自然排序，「第 2 話」會排在「第 10 話」前面。
- **目錄的章名就是子資料夾的名稱**，所以想在閱讀器看到什麼章名，就把資料夾取成那個名字。
- 點目錄的章名，會跳到該章的第一頁。
- 根目錄的圖片排在所有章節之前，**不會出現在目錄裡**。適合放封面。
- 只有第一層子資料夾算章節。更深層資料夾裡的圖片，會併入它所屬的第一層章節，依路徑排序，不會多出目錄項目。
- 沒有圖片的子資料夾不會產生章節。

### 支援的圖片與被忽略的檔案

- 支援 JPEG（`.jpg`、`.jpeg`）、PNG、WebP、GIF，副檔名大小寫都可以。
- 其他檔案（`.DS_Store`、`.txt`、`Thumbs.db` 等）會被自動忽略，不會造成錯誤。

## 4. 常用情境

### 美漫、台漫：從左到右翻頁

```bash
epubgen ./my-comic --direction ltr
```

預設是 `rtl`（從右到左）。這個參數同時決定閱讀器的翻頁方向，和雙頁模式裡的左右頁順序。

### 平板橫放：雙頁模式

```bash
epubgen ./my-comic --spread
```

橫放時，**封面單獨一頁**，其後的頁面兩兩並排，像實體書一樣。直放時仍然是單頁。

左右頁的順序跟著翻頁方向：

| 方向 | 封面之後 |
|------|----------|
| `rtl`（預設） | 第 2 頁在右、第 3 頁在左，第 4 頁在右、第 5 頁在左… |
| `ltr` | 第 2 頁在左、第 3 頁在右，第 4 頁在左、第 5 頁在右… |

手機建議不要加 `--spread`，小螢幕硬塞雙頁不好讀。

### 設定書名、作者、語言

```bash
epubgen ./my-comic --title "我的漫畫" --author "某某" --language ja
```

- 書名預設取自資料夾名稱。**輸出檔名也會跟著書名**，所以上面的指令會產生 `我的漫畫.epub`。書名裡有檔名不能用的字元（`/ \ : * ? " < > |`）時，輸出檔名會把它們換成 `_`，書名本身不受影響。
- 作者沒設定就不會寫入。
- 語言預設是 `zh-TW`，常用的還有 `ja`、`en`、`zh-CN`。格式要像 `ja`、`zh-TW`、`zh-Hant-TW`，寫成 `中文` 會顯示用法說明。

### 指定封面

預設用第一頁當封面。要換成別的圖：

```bash
epubgen ./my-comic --cover ./my-comic/cover-art.jpg   # 資料夾裡的圖
epubgen ./my-comic --cover ~/Pictures/front.png       # 資料夾外的圖
```

- 指定的是書裡的某一頁時，那一頁會被標成封面，不會重複加進書裡。
- 指定資料夾外的圖時，圖會被加進書裡當封面，但**不會多出一頁**。
- 相對路徑是從你目前所在的目錄算起，不是從輸入資料夾算起。

### 指定輸出位置

```bash
epubgen ./my-comic -o ~/Library/Mobile\ Documents/com~apple~CloudDocs/my-comic.epub
```

`-o` 指定的是**輸出檔的完整路徑**，不是資料夾。輸出的資料夾必須已經存在。`-o` 的優先順序高於書名，不會再依書名改檔名。

### 重新轉換：覆蓋舊檔

輸出檔已經存在時，`epubgen` 預設**拒絕覆蓋**，避免你不小心蓋掉東西：

```
epubgen: 錯誤：輸出檔已存在：/Users/你/Comics/my-comic.epub（要覆蓋請加上 --force）
```

確定要覆蓋時加上 `--force`：

```bash
epubgen ./my-comic --force
```

### 資料夾裡有壞圖

預設遇到損毀的圖片會停下來，並指出是哪個檔案：

```
epubgen: 錯誤：無法讀取圖片：第 2 話/7.jpg（要跳過損毀的圖片請加上 --skip-broken）
```

你可以修好或換掉那張圖，或者加上 `--skip-broken` 跳過，少數壞圖就不會擋住整本書：

```bash
epubgen ./my-comic --skip-broken
```

跳過的檔名會列在標準錯誤輸出裡：

```
epubgen: 已跳過 1 張無法讀取的圖片：
  - 第 2 話/7.jpg
已輸出：/Users/你/Comics/my-comic.epub（共 23 頁）
```

下載不完整的檔案、被截斷的圖片，也都會被當成損毀。

## 5. 圖片處理：WebP、GIF、壓縮與縮小

**預設不動你的圖片**：JPEG、PNG、GIF 的檔案位元組原樣放進 EPUB，畫質不會因為轉檔而下降。只有下面幾種情況例外。

### WebP 預設轉成 JPEG

不是所有閱讀器都能顯示 WebP（有使用者回報某些 Kobo 韌體會顯示空白），所以 WebP 預設會轉成高品質 JPEG（品質 95，透明處填白色）。確定你的閱讀器支援，想保留原檔時：

```bash
epubgen ./my-comic --keep-webp
```

### GIF 封面

Kobo 的封面不支援 GIF。如果封面是 GIF，`epubgen` 會另外用它的第一個畫格做一張 JPEG 封面，**頁面本身仍然是原始的 GIF**，不受影響。

### 縮小檔案：`--quality` 與 `--max-size`

超高解析度的掃圖會讓檔案很大，翻頁也會變慢。這兩個參數**只有在你給了才會處理**：

```bash
epubgen ./my-comic --max-size 1950            # 長邊最多 1950 像素
epubgen ./my-comic --quality 80               # 重新壓縮成品質 80
epubgen ./my-comic --max-size 1950 --quality 80
```

`--max-size PIXELS`

- 以圖片**長邊**為準，超過的圖等比例縮小，不會放大，比例不變。
- 縮小後：JPEG 維持 JPEG，PNG 維持 PNG（無損），GIF 與預設的 WebP 轉成 JPEG。GIF 轉出來只留第一個畫格，動畫會消失。
- Kobo 官方建議每頁不超過約 3,800,000 像素，大約 1950x1950。實機驗證時，每頁 3000x4500 的圖載入明顯比較慢，加上 `--max-size 1950` 可以改善。

`--quality 1-100`

- JPEG、WebP 會重新壓縮，數字越小檔案越小、畫質越差。80 左右通常看不出差別。
- **PNG 會轉成 JPEG**（有損）。如果想保留 PNG 的無損畫質，只用 `--max-size`，不要加 `--quality`。
- GIF 不受影響。
- 如果重新壓縮之後反而比原檔大，那張 JPEG 會維持原檔。

兩個參數處理過的圖，每一頁的版面尺寸都會跟著處理後的圖片，不會出現留白或變形。

## 6. 把書放進閱讀器

### Apple Books（iPhone、iPad、Mac）

- **Mac**：把 `.epub` 拖進 Books app。
- **iPhone、iPad**：用 AirDrop 傳過去，或在「檔案」app 裡點選檔案，選擇用 Books 開啟。

書會以固定版面開啟，圖片不會重排。

### Kobo

用 USB 線接上電腦，把 `.epub` 複製到閱讀器的根目錄，退出裝置後，等它匯入。

**副檔名說明**：Kobo 官方規格說，側載固定版面的書，要用 `.fxl.kepub.epub` 的副檔名，才會以 Kobo 自己的引擎顯示；維持 `.epub` 則會用 Adobe Digital Editions 引擎，官方沒有說明它能不能正確顯示固定版面。實際結果可能因機型與韌體而異。

建議做法：

1. 先直接用 `.epub` 試試看。
2. 如果版面顯示不正常（圖片錯位、被重排），把檔名改成 `.fxl.kepub.epub` 再試，例如把 `my-comic.epub` 改成 `my-comic.fxl.kepub.epub`。這只是改檔名，不用重新轉換。
3. 用 `.fxl.kepub.epub` 時，書籤與筆記功能會停用，封面縮圖也可能不顯示。這是 Kobo 的限制。

## 7. 批次轉換與腳本

### 結束代碼

| 結束代碼 | 意思 |
|----------|------|
| `0` | 成功 |
| `1` | 失敗（路徑不存在、沒有圖片、圖片損毀、輸出檔已存在、封面不存在…），錯誤訊息寫在標準錯誤輸出 |
| `2` | 參數不合法（例如 `--direction up`），會顯示用法說明 |

任何失敗都不會留下半成品檔案，所以可以放心在腳本裡用結束代碼判斷成敗。成功訊息（輸出路徑與頁數）寫在標準輸出，錯誤訊息寫在標準錯誤輸出，兩者不會混在一起。

### 一次轉換很多本

```bash
for d in ~/Comics/*/; do
  epubgen "$d" --skip-broken || echo "失敗：$d"
done
```

這會把 `~/Comics` 底下每個資料夾各轉成一本，輸出檔放在 `~/Comics/`。想重新轉換已存在的書，加上 `--force`。

注意：腳本裡的每個資料夾都是一本書。如果其中某個資料夾有多話，記得子資料夾就是章節。

## 8. 參數速查表

```
epubgen [選項] <輸入資料夾>
```

| 參數 | 說明 | 預設 |
|------|------|------|
| `--direction rtl\|ltr` | 翻頁方向，rtl 從右到左，ltr 從左到右 | `rtl` |
| `--spread` | 雙頁模式：橫放時封面單獨，其後兩兩並排 | 關閉 |
| `-o`, `--output PATH` | 輸出檔的完整路徑 | 輸入資料夾旁邊的 `<書名>.epub` |
| `--force` | 輸出檔已存在時覆蓋 | 拒絕覆蓋 |
| `--skip-broken` | 跳過損毀的圖片並列出檔名 | 遇到損毀圖片就報錯 |
| `--title TITLE` | 書名（輸出檔名也跟著書名） | 輸入資料夾名稱 |
| `--author NAME` | 作者 | 不寫入 |
| `--language CODE` | 語言代碼，例如 `ja`、`en`、`zh-TW` | `zh-TW` |
| `--cover IMAGE` | 指定封面圖片，可在資料夾內外 | 第一頁 |
| `--keep-webp` | 保留 WebP 原檔 | WebP 轉成 JPEG |
| `--quality 1-100` | 重新壓縮的品質 | 不重新壓縮 |
| `--max-size PIXELS` | 圖片長邊的像素上限 | 不縮放 |
| `--version` | 顯示版本 | |
| `-h`, `--help` | 顯示說明與所有預設值 | |

## 9. 疑難排解

**`epubgen: command not found`**
用 pipx 安裝後，要執行過 `pipx ensurepath` 並重新開啟終端機。

**`輸入路徑不存在` 或 `輸入路徑不是資料夾`**
路徑打錯了，或你給的是一個檔案而不是資料夾。路徑有空格時要用引號包起來，例如 `epubgen "./我的 漫畫"`。

**`資料夾裡沒有可用的圖片`**
資料夾裡沒有 JPEG、PNG、WebP、GIF。如果圖片都放在更深層的資料夾裡，確認它們在輸入資料夾的子資料夾底下（第一層子資料夾會成為章節）。

**`輸出檔已存在`**
想覆蓋就加 `--force`；不想覆蓋就用 `-o` 換一個路徑。

**`無法讀取圖片：xxx`**
那張圖片損毀、被截斷，或根本不是圖片（只是副檔名是圖片）。macOS 的壓縮檔解開後常有 `__MACOSX/._1.jpg` 這類檔案，副檔名是圖片但內容不是，這種檔案可以直接刪掉，或用 `--skip-broken` 跳過。

**目錄裡沒有出現我的章節**
章節名稱來自**第一層子資料夾**的名稱，而且資料夾裡要有圖片。根目錄的圖片不會出現在目錄裡。

**翻頁方向反了**
日漫用預設的 `rtl`，美漫和台漫加上 `--direction ltr`。

**閱讀器顯示 WebP 圖片是空白**
不要加 `--keep-webp`，讓 WebP 自動轉成 JPEG。

**Kobo 上圖片錯位或被重排**
把檔名改成 `.fxl.kepub.epub` 再試，見第 6 節。

**Kobo 上翻頁很慢**
圖片太大。用 `--max-size 1950` 縮小，見第 5 節。

**想知道 EPUB 有沒有問題**
產出的 EPUB 已用 [EPUBCheck](https://github.com/w3c/epubcheck) 驗證過。你也可以自己檢查：

```bash
java -jar epubcheck.jar my-comic.epub
```
